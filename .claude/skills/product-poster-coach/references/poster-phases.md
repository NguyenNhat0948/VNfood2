# プロダクトポスター フェーズ詳細（Phase 0〜 + アドオン）

SKILL.mdの原則を常時守る。採用担当者が見るのは「課題発見力・解決思考・実行力・メタ認知・技術力」。**埋める順は 03 検証実績 → 05 失敗と学び → 01 バグ**（この3つが揃えば "話しかけたい学生"）。

## Phase 0: 現在地の確認
1. プロダクトは今どの状態？（a: 人に使ってもらった / b: 動くものはある / c: 構想中）
2. 発表タイプは？（A-1 プロダクト＝使う人に届ける / A-2 エージェント＝Skills/MCPを開発者に届ける）
3. 発表日・掲示物の提出条件（A4カラー印刷・当日持参）を確認

**cの場合**: まず小さくても人に触ってもらう1回を先に。「友人5人でいいから使ってもらって、生の声を1つ持って帰ろう」と提案。

## Phase 1: 03 検証実績（最初に埋める・分水嶺）
1. 「実際に**何人が使った/何回試した**？小さくてOK、でも0は避ける」——数字の出どころを必ず確認
2. Before/After を1軸で（時間・手数・心理負荷のどれか1つ）。数字か画面で
3. **使ってくれた人の生の声を1つ**（ペンギンミックス等で得た声も◎）。誰の声かを添える
4. 🐧 企業評価の分かれ目。「すごい数字」でなく「本当に使われた事実」を選ぶ

## Phase 2: 05 失敗と学び（差別化）
1. 「試した中で**通用しなかったアプローチを1つ**」——隠させない
2. 「そこから**何が分かった**？（__を__に分けたら__になる、の形）」
3. 🐧 壁を学びに変える力が評価される。成功だけの発表は信用されない

## Phase 3: 01 バグ（現場の課題）
1. 「その困りごとを**最初に感じた具体的な場面**は？いつ・どこで・何をしていた？」——抽象論NG、シーンを1つ
2. 「誰が困っているか（自分ごとで）」「なぜ他のサービスでは解けないか」
3. 🐧「あるある」で終わらせない。写真か場面を1つ入れる

## Phase 4: 02 解決策（プロダクト）
1. 「使う人が**何ができるようになるか**、3行以内で」——機能を並べない
2. 変化が見えるUI/UXスクショを1枚（`figures/` に置く）
3. 🐧 VPCで考えた価値をそのまま反映するとブレない

## Phase 5: 04 技術構成（推奨）
1. 「どの技術を、**なぜ**選んだか」——賢さは借りて（Claude/GPT等）、力仕事は自前で（ローカル/大量処理）
2. A-2/研究寄りなら簡単なアーキ図を1枚
3. 🐧 ざっくりでOK。「賢さ借用・力仕事自前」の考えが伝われば十分

## Phase 6: 06 次の一手（強く推奨）
1. 「次に**どう方向転換**する？ / 何を試す？ / 誰に相談したい？」
2. 🐧「完成した」より「途中＋次はこう変える」が続けていく力の証明

## Phase 7: ヘッダー＋フッター
1. タイトル（プロダクト名・大きく）＋**タグライン**「誰の・何が・どう変わるか」1行（価値から）
2. キービジュアル/決めスクショ（パッと見て内容が分かる）
3. フッター必須: **顔写真**（プライバシー配慮ならイラスト可）＋**連絡先QR**（email/SNS）＋**プロダクト/GitHub QR**
4. 「話したいこと」1行（採用担当と何を話したいか）

## Phase 8: 仕上げ＋印刷＋アクションリスト
1. `references/poster-format.md` に従いブラウザで通し確認 → A4縦PDFに出力
2. アクションリスト（必ず含める）:
   - [ ] QRコードの生成（プロダクトURL・連絡先）と貼り込み
   - [ ] 顔写真 or イラストの用意
   - [ ] キービジュアル/スクショの `figures/` 配置
   - [ ] 【要検証】タグの数字の裏取り
   - [ ] A4カラー印刷・当日持参
   - [ ] 想定Q&A 5問（「それ既存サービスと何が違う？」系）

## アドオンメニュー（押し付けない）
**A. 検証の上積み**: 追加ユーザーテスト設計、定量指標（継続率・NPS等）の取り方
**B. デモ強化**: 当日デモ/GIFの用意、Vercel等の公開URL整備、当日フリーズ回避手順
**C. 見せ方の高度化**: 図・スクショの整理（1図1メッセージ）、狙う賞の意識、英語1行サマリー
**D. GitHub整備**: READMEの3行実行手順、公開リポジトリ整備（第13回提出用）
